# M1.06 Subunit 5 Regression Addendum

These stable IDs extend the HSE Verify regression register for defects discovered during the cumulative M1.06 isolation, migration, recovery and acceptance unit. They remain permanent even after M1.06 closes.

| ID | Defect prevented | Root cause | Required behaviour | Permanent automated guard | Status |
|---|---|---|---|---|---|
| REG-070 | A pull-request run is described and stored as an “exact-head gate” even though GitHub Actions actually checks out the synthetic `refs/pull/<n>/merge` commit, so the recorded SHA is not the branch head that the merge lock later verifies | `actions/checkout` used its default PR-event ref and `HSE_RELEASE_SHA`/artifact naming used `github.sha`; on `pull_request` events both values refer to GitHub's generated merge commit, not `github.event.pull_request.head.sha` | PR verification must explicitly check out the immutable pull-request head SHA and use that same SHA as the release/evidence identity. The later merged-`main` run separately proves integration with `main`. A pass must never be labelled exact-head unless the code actually executed is the branch head | `.github/workflows/worker-foundation-ci.yml` derives `VERIFIED_SHA` from `github.event.pull_request.head.sha` for PR events and `github.sha` otherwise, checks out `ref: ${{ env.VERIFIED_SHA }}`, supplies `HSE_RELEASE_SHA` from the same value and names evidence with it; `scripts/check-engineering-automation.mjs` protects those workflow markers | PROTECTED |
| REG-071 | The cumulative M1.06 runtime suite cannot even load the real accepted upload service because a transitive production module uses the repository's `@/lib/*` TypeScript path alias and the standalone CommonJS harness understands only relative imports | The first Subunit 5 dependency walker ignored non-relative imports and TypeScript transpilation preserved `@/lib/config/environment` in emitted CommonJS, so both cumulative test files terminated at module load with `Cannot find module '@/lib/config/environment'` before any product assertion executed | The cumulative runner must treat the canonical `@/lib/*` alias as a source-root import during dependency discovery and rewrite that alias to the correct relative emitted module specifier in the isolated runtime copy. Production source imports must remain unchanged; unresolved/escaped aliases must fail closed rather than being mocked away | `scripts/run-m1-06-final-tests.mjs` uses one `resolveSourceImport` contract for both relative and `@/lib/*` dependencies, source-root confinement and `runtimeSpecifier` alias rewriting before transpilation; `scripts/check-m1-06-final-acceptance.mjs` and `scripts/check-engineering-automation.mjs` require these markers and forbid removing alias support | PROTECTED |
| REG-072 | Complete M1.06 rollback/reapply fails after later immutable secure-file audit facts already exist | Historical M1.06 up migrations `0012_secure_file_upload_quarantine` and `0013_secure_file_malware_scan` each recreated the shared audit-action check using only the vocabulary known when that migration was first written. The later 0013/0014 down migrations correctly preserve immutable scan/access history, so reapplying 0012 first rejected later scan/access facts; after repairing 0012, reapplying 0013 then rejected retained signed-access facts. Both failures are the same root cause: a historical replay step narrowed an append-only audit vocabulary | Every historical M1.06 migration that redefines the shared audit-action check must preserve the current accepted M1.06 secure-file vocabulary. Because 0012 and 0013 were already accepted with different up-SQL checksums, each repaired SQL file has one explicit legacy checksum bound to one exact repaired checksum. Only those named legacy/current pairs are accepted; unknown checksums and later unapproved edits fail closed. Approved legacy ledger rows normalize once to the repaired checksum without changing the original `release_sha` | `database/migrations/0012_secure_file_upload_quarantine.up.sql` and `0013_secure_file_malware_scan.up.sql` both preserve upload/scan/signed-access audit actions; `scripts/lib/migrations.mjs` pins both exact legacy/current pairs and normalizes only `approved_repair`; `tests/platform/migration-checksum-repair.test.mjs` validates every pair and rejects unknown/tampered values; `tests/platform/m1-06-final-restart-migration.test.mjs` retains later audit history through the entire rollback/reapply; `scripts/check-m1-06-final-acceptance.mjs` source-protects the complete replay contract | PROTECTED |

Additional serious defects discovered by the Subunit 5 cumulative gate must receive the next stable ID before M1.06 can close.

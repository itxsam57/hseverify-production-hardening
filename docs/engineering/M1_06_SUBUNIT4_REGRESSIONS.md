# M1.06 Subunit 4 Regression Addendum

These stable IDs extend the HSE Verify regression register for defects discovered while building M1.06 Subunit 4. They remain permanent even if the signed preview/download implementation or engineering tooling is later refactored.

| ID | Defect prevented | Root cause | Required behaviour | Permanent automated guard | Status |
|---|---|---|---|---|---|
| REG-055 | Malformed signed capability timestamps reach integer/time arithmetic without first proving their runtime type | The first token parser passed untrusted JSON fields directly to integer checks, relying on TypeScript casts/narrowing rather than proving `iat` and `exp` are numbers at the runtime boundary | Signed token parsing must require numeric `iat` and `exp` before safe-integer, lifetime, future-skew or expiry checks; strings, fractional values and malformed times fail closed | `src/lib/secure-files/secure-file-access-domain.ts` explicitly proves numeric types; `tests/secure-files/secure-file-access-domain.test.mjs` rejects string/fractional/malformed timestamps | PROTECTED |
| REG-056 | Historical/corrupt display filename metadata injects path/control characters into `Content-Disposition` even though the filename was validated earlier in the upload lifecycle | The first response-header draft assumed accepted stored metadata could never be damaged later and encoded it without re-running the canonical filename validator at the final response boundary | Stored display filename must be revalidated immediately before header construction; the ASCII fallback remains server-generated, while the validated stored filename is emitted only as an encoded UTF-8 parameter. Control/path characters fail closed | `src/lib/secure-files/secure-file-access-core.ts` reuses `normalizeSecureFileDisplayFilename`; `tests/secure-files/secure-file-access-core.test.mjs` covers CR/LF and path injection plus Unicode/quote encoding | PROTECTED |
| REG-057 | The signed-access unit gate removes the production `server-only` boundary merely to make standalone Node tests compile | The first isolated strict test compiler did not know Next's marker-only `server-only` module, so TypeScript stopped before unit execution | Production signed-access modules must retain `import "server-only"`; the isolated test compiler gets only a test-scope ambient module declaration, and the runner removes only the emitted marker import from its temporary compiled copy after strict compilation | `tests/types/server-only.d.ts`, `tsconfig.secure-access-tests.json` and `scripts/run-secure-access-tests.mjs` preserve production source while allowing isolated strict unit execution; full project typecheck/build still validate the real server-only imports | PROTECTED |
| REG-058 | The signed-access source guard rejects safe bounded audit metadata such as `byteSize`, encouraging removal of useful audit facts merely to obtain a green gate | The first guard searched the entire adapter with an unbounded case-insensitive `bytes` substring, so the letters at the start of `byteSize` were misclassified as raw file bytes | The guard must classify identifier semantics: bounded byte counts such as `byteSize`/`byteLength` are allowed, while raw byte collections, tokens, URLs, object keys, hashes, storage authority and secrets remain forbidden in the audit adapter | `scripts/check-secure-file-access.mjs` self-tests allowed and forbidden identifier families and scans the real audit adapter using the same semantic predicate | PROTECTED |
| REG-059 | Mandatory AI/build context says old bricks are still in progress or not started after those bricks have already been accepted, allowing a future developer to branch from the wrong milestone boundary | Volatile milestone state was duplicated across `PROJECT-PROFILE.md`, `PROJECT-TEST-MATRIX.md`, `HSE_BUILD_MEMORY.md`, `MILESTONE_PATH.md` and `LATER.md`, while `check:engineering` only proved that files/keywords existed and still hard-coded an old M1.04 handoff marker | The exact current gate, permanent milestone record, compact memory, profile, test matrix and Later register must agree on M1.01–M1.05 acceptance, M1.06/Subunit state and canonical M2/M3 counts; resolved Later items must not remain open; CI must fail on contradictory/stale markers | `scripts/check-engineering-automation.mjs` cross-checks the authoritative context set and canonical roadmap markers during every quick/full gate | PROTECTED |
| REG-060 | Signed-access route-surface and migration rollback/reapply tests exist in the repository but never execute, allowing a green gate without proving those required contracts | The first runtime runner invoked only the PGlite access and audit tests; newly added `secure-file-access-routes.test.mjs` and `secure-file-access-migration-stack.test.mjs` were orphan test files not referenced by any executable gate | Every permanent signed-access platform test must be invoked by the signed-access integration runner that is itself required by `test:integration` and the complete gate | `scripts/run-secure-access-runtime-tests.mjs` invokes runtime, audit, migration-stack and route-surface tests together; the engineering/source gate protects that runner wiring | PROTECTED |
| REG-061 | Build-context consistency CI fails when two authoritative files express the same accepted state with different harmless prose, encouraging wording edits instead of state validation | The first REG-059 implementation checked one exact English sentence (`5 of 12 Milestone 1 bricks are DONE`) instead of the underlying milestone facts | Context checks must validate semantic facts independently: progress count `5/12` or `5 of 12`, M1.05 DONE, M1.06 IN PROGRESS, Subunit 4 IN PROGRESS, canonical M2.13/M3.12 endpoints and open/resolved Later IDs; prose formatting/layout may differ | `scripts/check-engineering-automation.mjs` validates shared brick facts and then uses document-specific stable structure/IDs for Subunit 4 rather than one preferred sentence/window | PROTECTED |
| REG-062 | Server-only App Router API changes are classified as a visible UI change and generate a fake generic browser test, making owner acceptance misleading | The fallback classifier treated every unmatched `src/app/**` path as browser UI, including `src/app/api/**/route.ts` | App Router API routes must classify as internal server API surfaces unless a separate real page/component/known visible feature changes; unknown non-API pages/components must still fail safe into visible manual testing | `scripts/lib/handoff-domain.mjs` has explicit internal `API_SURFACE`/`SECURE_FILES` rules and excludes `src/app/api/` from the unknown-UI fallback; `tests/engineering/handoff-domain.test.mjs` proves API-only secure-file changes require no invented browser test while an unknown page still does | PROTECTED |
| REG-063 | An authenticated signed-access caller can force the authorization endpoint to buffer far more than its advertised 4 KB request limit before rejection | The first route used `await request.text()` and then measured the resulting string; authentication happened first, but the actual body size check still happened only after complete buffering | The route must reject a declared oversize body before reading, stream the actual body through a hard byte ceiling independent of `Content-Length`, reject malformed length/UTF-8/JSON, cancel on overflow and only then pass parsed JSON to the exact request contract | `src/lib/secure-files/secure-file-access-request.ts` performs bounded streaming; `tests/secure-files/secure-file-access-request.test.mjs` covers honest/deceptive/malformed length, actual overflow, invalid UTF-8/JSON and invalid limits; `scripts/check-secure-file-access.mjs` forbids `request.text()`/`request.json()` bypasses and requires the bounded reader | PROTECTED |
| REG-064 | A correct no-browser-test decision is accompanied by wording that calls real internal product/security changes an “engineering-only installation,” producing a misleading owner acceptance record | The handoff formatter was originally written for governance-only changes and reused that explanation whenever visible-feature count was zero, even when the classifier correctly found internal API/security product changes | Zero visible features must mean only that no browser-visible surface changed; the handoff must still identify internal product/security areas, assign them to automated verification, avoid invented owner browser work and describe production-provider limitations without implying accepted local/test adapters are absent | `scripts/report-manual-handoff.mjs` uses visibility-neutral zero-test wording and precise provider language; `scripts/check-engineering-automation.mjs` requires the corrected phrases and forbids the obsolete “engineering-only installation” / “Changes are limited to engineering standards” explanations | PROTECTED |
| REG-065 | Cross-owner, revoked-session or suspended-membership denial from the secure-file repository escapes the signed-access route's intended non-enumerating 404 contract and can become a 500 | The accepted secure-file repository and the new signed-access layer each define their own `SecureFileAccessDeniedError`; the first core implementation passed repository exceptions through without translating between those layer contracts | Signed-access issue/use lookups must translate only the underlying secure-file repository denial into the signed-access denial class caught by the HTTP route; unexpected database/operational errors must continue to surface as server failures | `src/lib/secure-files/secure-file-access-core.ts` centralizes lookup in `findAuthorizedFile`, explicitly maps `SecureFileRepositoryAccessDeniedError` and rethrows all other errors; `tests/secure-files/secure-file-access-core.test.mjs` proves translation versus generic failure and the real PGlite Worker/company cross-scope, revoked-session and suspended-membership tests assert the signed-access denial class | PROTECTED |
| REG-066 | The signed-access runtime test suite fails to load a real production dependency, or silently stops testing it, whenever a tested module gains a new transitive relative import | The first runtime harness maintained a hand-written flat `SOURCE_FILES` list; `audit-repository.ts` already depended on `tenant-scoped-command-guard.ts`, which was omitted | The runtime harness must derive and compile the complete relative TypeScript dependency closure from fixed trusted entry modules, reject unresolved/escaped relative imports and stub only the explicitly declared database adapter boundary | `scripts/run-secure-access-runtime-tests.mjs` recursively uses TypeScript import preprocessing and source-root confinement from `ENTRY_FILES`; the engineering gate protects dependency-closure markers and the runtime suite must load the real audit/authorization repositories | PROTECTED |
| REG-067 | The permanent signed-access migration rollback/reapply test is present but cannot prove anything because it calls the rollback helper with the wrong signature and queries a migration-history table that does not exist in this repository | The first test was written against an imagined status-ledger contract instead of the repository's actual guarded `rollbackLatestMigration(database, environment)` plus `hse_schema_migrations`/`migrationStatus` model | The proof must use the real test-environment destructive-rollback acknowledgement, real rollback helper contract and `migrationStatus`; after rolling through 0014 it must prove the migration is pending with a matching checksum, immutable audit history/vocabulary survives, and reapply records the new release SHA | `tests/platform/secure-file-access-migration-stack.test.mjs` uses `migrationStatus`, guarded rollback acknowledgement and the real helper signature; it is executed by `test:secure-access-runtime` and the complete gate | PROTECTED |
| REG-068 | A real private-storage integrity or I/O failure is converted into the same non-enumerating access denial used for a missing/tampered object, hiding an infrastructure failure as a fake 404 | The first read path wrapped `storage.read()` in a blanket catch and replaced every thrown storage error with `SecureFileAccessDeniedError`, even though the accepted storage adapter already returns `null` for a missing object and throws only for invalid/insecure paths or operational I/O failures | Missing objects and byte-size/SHA mismatch remain non-enumerating access denial, but a thrown trusted-storage error must propagate to the generic server-error boundary so the failure is not mislabeled or silently hidden | `src/lib/secure-files/secure-file-access-core.ts` directly awaits the trusted storage read and only maps null/tamper to access denial; `tests/secure-files/secure-file-access-core.test.mjs` proves a thrown storage failure keeps its original operational error identity; full route/service gates keep output generic | PROTECTED |
| REG-069 | A completed historical product regression fails after a legitimate engineering-memory refactor because it asserts obsolete governance headings instead of the product behavior it owns | The Worker-registration owner-repair test mixed two unrelated responsibilities: registration UI/OTP regression and exact prose checks for `Build priority rule` / generic `BUILD-PIN` format inside a volatile build-memory document. The underlying build procedure still existed, but a harmless documentation restructuring failed the complete gate | Product regressions must assert their product boundary only. Root-cause/brick sequencing rules belong to the engineering contract and must be checked by semantic behavior markers, not old section titles. Existing concrete Worker OTP BUILD-PIN markers remain protected by the OTP test itself | `tests/platform/worker-registration-owner-repair.test.mjs` no longer reads `HSE_BUILD_MEMORY.md`; `scripts/check-engineering-automation.mjs` protects semantic root-cause, exact-head gate and no-next-brick procedure markers and forbids reintroducing cross-domain memory assertions into the Worker registration regression | PROTECTED |

# HSE Verify M2.02–M2.06 Hard Browser QA Plan

## Purpose
Prove the implemented Phase 1 surfaces in a real Chromium browser against a clean database. Browser-visible behavior is authoritative: no direct service calls are accepted as substitutes for a user workflow.

## Method
- Run on an isolated QA branch.
- Use a clean PGlite data directory and the development/test-only authentication sandbox.
- Start the real Next.js application.
- Drive Chromium with Playwright using accessible labels, roles and visible text.
- Bootstrap Root through `/auth/sandbox/bootstrap-root`; enroll password + TOTP through the real staff invitation flow.
- Provision Admin and Verifier from the Root portal and complete their password + TOTP enrollment through visible UI.
- Create Worker and Company accounts only through their public registration/verification pages and sandbox inbox; never inject sessions or browser cookies.
- Exercise M2.02–M2.06 forms and cross-role state transitions in browser-visible order.
- Run desktop and mobile smoke coverage, reload/back/direct-link/invalid-ID checks, portal isolation, console/page-error collection, and screenshots/traces on failure.
- Any defect gets a reproducer first, root-cause analysis second, minimal fix third, then browser + targeted regression rerun.

## Browser gates
1. Zero state/public entry: home, all login portals, worker/company registration, test-only sandbox visibility only in test mode.
2. Authentication: Root bootstrap; staff invitation acceptance; password; mandatory MFA; login; wrong-portal isolation.
3. M2.03 Admin: create framework, publish effective policy, visible persistence after reload.
4. M2.04 Admin: create valid questions, reject malformed/duplicate input visibly, revise and toggle status, persist after reload.
5. M2.05 Admin: create/revise assessment blueprint, visible persistence.
6. M2.06 Admin: create/revise/deactivate/reactivate catalogue entry, visible persistence.
7. Company: registration/login; tightening policy override; weakening override rejected; Assurance Order create/validate/submit; locked policy visible.
8. Worker: registration/login; evidence upload/persistence; direct-link isolation; available-assessment eligibility before/after exact approved current qualification.
9. M2.02 Verifier: review queue; claim; preview/access; approve/reject/request-changes; conflict path; copied task ID denial; Worker state reflection.
10. Stress/UX: refresh, browser Back, double action protection, two-tab stale state, copied/invalid IDs, desktop and 390px mobile viewport, visible loading/error/empty states, no console/page errors.

## Milestone boundary
M2.07 has not been implemented. Attempt start, one-question-at-a-time runtime, answer autosave/resume, attempt timer and scoring/result behavior are excluded from pass/fail and must not be simulated by this QA harness.

## Completion evidence
- Exact QA branch SHA.
- Chromium workflow status and job logs.
- Failure screenshots/traces/artifacts.
- Confirmed defects and fixes.
- Targeted M2.02–M2.06 regression scripts, typecheck and lint green after any fix.

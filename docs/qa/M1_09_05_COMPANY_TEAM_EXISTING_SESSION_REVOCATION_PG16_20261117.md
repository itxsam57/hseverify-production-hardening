## Root fix, safe scope, and exact retests

- `CompanyTeamService.changeMemberStatus` now updates all existing Company-role session records for the target `account_id` with `revoked_at` and specific `revocation_reason=company_team_membership_suspended` or `company_team_membership_revoked`, **inside the SAME transaction as membership status and immutable Team audit**. A reactivation never resets existing session revocation. Other roles, the Owner and foreign tenant/account sessions are untouched. Successful Team audit includes number of Company sessions revoked.
- `AuthenticationRepository.insertSession` now requires active Company membership for `active_role='company'`, obtaining PostgreSQL `FOR SHARE` on the specific active membership row to **serialize new Company token issuance versus Owner membership suspension/revocation**. Other role sessions continue to follow unchanged active-account rule. If login commits first, status transition sweeps that token; if status transition wins, login must wait then deny. Avoided global account lockout and historical migration checksum mutation; **no new schema migration**.

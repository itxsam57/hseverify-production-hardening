## Security decisions

- Browser input cannot set actor account, role, tenant, membership, permission, outcome authority or timestamps.
- Native timestamps are generated by the database.
- Existing authentication timestamps are retained because they were generated by the accepted server authentication boundary.
- Audit records intentionally do not use destructive foreign-key cascades; opaque actor and tenant references remain historical facts.
- Database triggers reject every update and delete, including attempts outside the application repository.
- Sensitive metadata keys such as passwords, passcodes, OTPs, tokens, secrets, credentials, cookies and authorization values are rejected for native events and recursively removed from the compatibility bridge.
- No UI is an authorization boundary.
- Root and Administrator platform audit reads still revalidate the live session and account.
- Company audit reads reuse the accepted transactional tenant command guard.
